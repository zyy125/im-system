# Frontend Gap Checklist

本文档用于盘点当前前端相对后端能力的缺口，并给出推荐开发顺序。

目标不是重复接口文档，而是把“还没做的业务”拆成前端可执行待办。

## 1. 当前结论

前端已经覆盖的主链路：

- 注册、登录、登出、自动 refresh
- 当前用户恢复
- 好友申请发送/接受/拒绝
- 好友列表展示
- 会话列表展示
- 打开会话、历史消息、实时消息、已读提示
- `sync.required` 补洞

前端还没有完整覆盖的后端能力：

- 用户资料页
- 在线状态查询页
- 头像上传与清空
- 删除好友
- 隐藏会话
- 创建群
- 群详情
- 群成员列表
- 改群名
- 邀请成员
- 移除成员
- 退群
- 解散群
- 消息失败重发

## 2. 推荐优先级

建议按下面顺序推进：

### P0

1. 头像上传与清空
2. 删除好友
3. 隐藏会话
4. 消息失败重发

### P1

1. 创建群
2. 群详情页
3. 群成员列表
4. 邀请成员

### P2

1. 改群名
2. 移除成员
3. 退群
4. 解散群
5. 用户资料页
6. 在线状态独立展示

## 3. 详细待办

## 3.1 用户域

### 任务：头像上传

- 状态：未落地
- 后端接口：
  - `POST /api/v1/users/avatar`
- 请求格式：
  - `multipart/form-data`
  - 字段：`file`
- 前端待做：
  - 在当前用户区域增加“上传头像”入口
  - 选择图片后调用上传接口
  - 上传成功后刷新 `/api/v1/users/me`
  - 同步更新本地 `currentUser.avatar`
- 验收：
  - 上传后当前用户头像立即更新
  - 会话列表、好友列表、申请列表中的头像显示更新后的地址

### 任务：清空头像

- 状态：未落地
- 后端接口：
  - `DELETE /api/v1/users/avatar`
- 前端待做：
  - 在头像菜单里增加“清空头像”
  - 成功后刷新当前用户信息
- 验收：
  - 清空后头像恢复为默认占位

### 任务：用户资料页

- 状态：未落地
- 后端接口：
  - `GET /api/v1/users/:id`
- 前端待做：
  - 在会话头部或好友项增加“查看资料”
  - 展示 `username`、`avatar`、`online`
- 验收：
  - 可以查看任意已知用户基础信息

### 任务：在线状态页/显式查询

- 状态：未落地
- 后端接口：
  - `GET /api/v1/user/online`
- 前端待做：
  - 评估是否需要独立使用该接口
  - 如果保留当前 purely WS 驱动方案，可不单独做页面
- 备注：
  - 这一项优先级较低

## 3.2 好友域

### 任务：删除好友

- 状态：未落地
- 后端接口：
  - `DELETE /api/v1/friends/:id`
- 前端待做：
  - 在好友项或会话头部增加“删除好友”
  - 操作前做确认
  - 成功后刷新：
    - `/api/v1/friends`
    - `/api/v1/conversations`
- 验收：
  - 删除后好友列表中消失
  - 单聊关系同步失效或不再作为好友展示

## 3.3 会话域

### 任务：隐藏会话

- 状态：后端已支持，前端无入口
- 后端接口：
  - `POST /api/v1/conversations/:id/hide`
- 前端待做：
  - 在会话项或会话头部增加“隐藏会话”
  - 隐藏后刷新会话列表
- 验收：
  - 被隐藏会话不再出现在消息栏
  - 群聊仍能通过群列表进入

## 3.4 群聊域

### 任务：创建群

- 状态：未落地
- 后端接口：
  - `POST /api/v1/conversations/groups`
- 前端待做：
  - 增加“创建群聊”入口
  - 支持输入群名
  - 支持从好友中选择初始成员
- 验收：
  - 创建成功后自动进入该群会话

### 任务：群详情页

- 状态：未落地
- 后端接口：
  - `GET /api/v1/conversations/groups/:id`
- 前端待做：
  - 在群会话头部增加“群详情”
  - 展示：
    - 群名称
    - 群头像
    - owner_id
    - member_count
    - my_role
- 注意：
  - UI 不需要展示 `owner_id` 原始数字给普通用户，但前端内部会用到

### 任务：群成员列表

- 状态：未落地
- 后端接口：
  - `GET /api/v1/conversations/groups/:id/members`
- 前端待做：
  - 群详情页增加成员列表
  - 显示头像、用户名、角色、在线状态

### 任务：改群名

- 状态：未落地
- 后端接口：
  - `POST /api/v1/conversations/groups/:id/name`
- 前端待做：
  - 仅在当前用户有权限时显示入口
  - 提交后刷新群详情和会话标题

### 任务：邀请成员

- 状态：未落地
- 后端接口：
  - `POST /api/v1/conversations/groups/:id/invite`
- 前端待做：
  - 在群详情里选择好友邀请入群
  - 提交 `member_ids`

### 任务：移除成员

- 状态：未落地
- 后端接口：
  - `POST /api/v1/conversations/groups/:id/members/:user_id/remove`
- 前端待做：
  - 仅群主可见
  - 在成员列表里提供“移除”

### 任务：退群

- 状态：未落地
- 后端接口：
  - `POST /api/v1/conversations/groups/:id/leave`
- 前端待做：
  - 在群详情页提供“退出群聊”
- 注意：
  - 群主不可直接退群，需正确处理冲突错误

### 任务：解散群

- 状态：未落地
- 后端接口：
  - `POST /api/v1/conversations/groups/:id/dismiss`
- 前端待做：
  - 仅群主可见
  - 操作前必须二次确认

## 3.5 消息域

### 任务：消息失败重发

- 状态：部分落地
- 当前现状：
  - 已有 `failed` 状态
  - 但无显式重发入口
- 前端待做：
  - 为失败消息增加点击重发或按钮重发
  - 重发时重新生成 `msg_id`
  - 保持原始 `content`
- 验收：
  - 断网或 WS 失败后，用户可以手动重发

### 任务：更完整的同步与恢复提示

- 状态：部分落地
- 当前现状：
  - 已处理 `sync.required`
  - 但 UI 上缺少显式“正在同步/已补齐”提示
- 前端待做：
  - 评估是否加轻量状态提示
- 优先级：
  - 中低

## 4. 推荐执行方式

如果继续让大模型补前端，建议按以下批次推进：

### 批次 1

- 头像上传
- 清空头像
- 删除好友
- 隐藏会话
- 消息失败重发

### 批次 2

- 创建群
- 群详情
- 群成员列表
- 邀请成员

### 批次 3

- 改群名
- 移除成员
- 退群
- 解散群

## 5. 实施约束

后续继续补前端时，仍然必须遵守：

1. 所有用户主标识统一使用 `user_id`
2. 登录统一使用 `username + password`
3. 好友申请现在统一通过 `username`
4. 消息游标只使用 `seq`
5. 不为后端未实现的功能添加伪入口
6. 如果新增 UI 控件，必须确认后端存在对应接口
